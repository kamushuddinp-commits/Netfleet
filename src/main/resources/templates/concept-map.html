Many-to-Many (M:N) ER Mapping via Dynamic Arrays & Reference Passing

Comprehensive architectural breakdown of how LearnHub models the M:N relationship in pure Java.

1. Dynamic Array Storage

Instead of static arrays (Course[], Student[]) which have fixed memory bounds, both Student and Course use java.util.ArrayList.

// Inside Student.java & Course.java private final ArrayList<Enrollment> enrollments = new ArrayList<>();
  • Dynamic memory expansion upon enrollment
  • Automatic heap reallocation and index shifting
  • O(1) amortized insertion with ArrayList.add()
2. Object Reference Passing

Java manipulates objects by reference. When an enrollment is formed, the references of Student and Course are passed directly into the associative entity.

// Enrollment.java constructor public Enrollment(String id, Student student, Course course) { this.student = student; // heap reference this.course = course; // heap reference }
  • Zero redundant data duplication in heap memory
  • Mutating Course attributes immediately reflects across all enrolled Students
  • Bidirectional navigation via reference traversal
3. Associative Join Entity

In database ER theory, M:N relationships are normalized through a join table. In Java OOP, this is achieved through the Enrollment associative class.

// Linking references bidirectionally student.addEnrollment(enrollment); course.addEnrollment(enrollment);
  • One Student → Many Enrollments → Many Courses
  • One Course → Many Enrollments → Many Students
  • Preserves relationship metadata (enrollment date, grade, status)
